|---|---|

Synthetic. Released under the repository's MIT license. |
| `huge-page.pdf` | Written by `make_pdf_fixtures.py`: one page 14400×144 pt (200×2 inches, the largest page size PDF allows), left half red, right half blue. At 150 DPI it would be 30000 px wide, over the 10000 px render limit. Synthetic. MIT. |

| `metadata.pdf` | Written by `make_pdf_fixtures.py`: one 400×300 pt page (white, a blue rectangle, a 2×2 image) carrying everything Remove metadata takes out: document information (Title, Author, Subject, Keywords, Creator, Producer, both dates and a custom `/Company`); XMP on the catalog, the page and the image; `/PieceInfo` on the catalog and the page; an attachment `secret.txt` in the embedded files name tree, also shown by a hidden file attachment annotation; document JavaScript in the names tree, a JavaScript `/OpenAction`, catalog `/AA` (on close), page `/AA` (on open, with a chained `/Next`, and a Rendition action with `/JS` on close) and a link whose action is JavaScript. The link's `/Contents` is UTF-16 text outside ASCII ("Liên kết" and U+1F517). It also has a bookmark that must stay. Names and dates are invented. Synthetic. MIT. |
| `password-protected.pdf` | `three-colours.pdf` encrypted by qpdf 12.4.2 (from `scripts/fetch-deps.ps1`) with AES-256, user and owner password `flevert-test`. AES uses a random salt, so regenerating gives different bytes with the same content. MIT. |

Regenerate with:

```
python make_pdf_fixtures.py .
..\..\..\deps\qpdf\bin\qpdf.exe --encrypt --user-password=flevert-test --owner-password=flevert-test --bits=256 -- three-colours.pdf password-protected.pdf
```

The 2 001-page document, the document information written inside a trailer, the catalog nested 490 deep, the 200 000- and 500 000-page documents that keep qpdf busy for the cancel and kill tests, the non-PDF file and the copies at Unicode and long paths are made at run time by the tests themselves (`TestPdf.cs`). So are the malicious pages of the PDF worker tests: `WriteStallingPage` (one A4 page whose shading is a million page-sized triangles, 60 KB, about 40 minutes of pdfium work) and `WriteSquarePage` (a 14 400 pt square page, 400 MB of pixels at 10 000 px).

Malicious and broken PDFs (T18) are written at run time by `MaliciousPdf.cs`, with the .NET base library only; nothing is downloaded and none of it is real malware. `MaliciousPdf.All` lists each with what it is: Flate bombs that inflate to 4 GiB (content stream, image, an unused stream under two Flate filters, an object stream), page-tree loops and self-references, 100 000 and 2 001 pages, /Count lying low and high, giant, zero and inverted MediaBoxes, broken cross-reference tables and a truncated file, a PNG, a zip and an empty file named .pdf, nesting 100 000 deep, 300 000 objects, launch and JavaScript actions (the launch action would write a marker file in %TEMP%; a control test runs it by hand), an unknown security handler, and a signed (structurally, not cryptographically) PDF. The bombs repeat one sync-flushed zlib block for each MiB of zeros, so 4 GiB cost no compression time; a test inflates a small one whole, Adler-32 included. `WriteManyObjects` (a million objects on one page, 53 MB, about 13 s of qpdf) is the slow input of the cancel and kill tests, and `TestPdf.WriteStallingPages` the slow pages of the worker's whole-file budget test.

The PDFs of Compress for sharing and Convert > Text (v0.2.1) are written at run time too, never committed. `SharingPdf.cs` draws scanned pages with the ImageMagick of this solution (word-sized blocks on paper, a gradient block, a brightness noise like a scanner's, fixed seeds) and writes them as 300 DPI JPEGs into PDFs: twenty different pages, an image drawn at two sizes, one with a soft mask, Flate, CMYK, 1-bit, inside a form, shown again by a stamp annotation. `TestTextPdf.cs` writes Vietnamese text with pdfium and the Arial of Windows, whose licence keeps it out of the repository. Python's standard library cannot encode the JPEGs, and twenty scanned pages would be about 22 MB of binaries.
